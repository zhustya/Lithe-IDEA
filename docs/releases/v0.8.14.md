### 重点更新

首次搜索会在后台建立全文索引；索引就绪后，罕见关键词和中文词的搜索从几十秒降到毫秒级，完整计数不再逐文件扫描。

#### ✨ 新功能

- 点击项目搜索或全局搜索的结果打开文件时，目标行滚动到编辑器中间并淡出高亮，跳转位置不再需要自己寻找。
- 搜索面板在建立索引期间显示“正在建立搜索索引”，冷查询超时后保持“搜索中”，索引就绪会自动重查。

#### ⚡ 改进

- 项目搜索和全局文本搜索首次查询时在后台调用 Core 的 `workspace.searchIndex.warm`，每个可见性变体只建一次；索引在关闭项目时释放。
- 中文等非 ASCII 查询也使用字节三元组收窄候选文件；同一工作区里中文词的搜索从十几秒降到毫秒级。
- 完整匹配计数复用同一候选集，不再为每个查询读取整个工作区。
- 完整计数在输入停顿后再开始，连续输入不会反复触发整库扫描。

#### 🛠 修复

- 修复大型工作区里罕见关键词搜索几乎必然超时、每次输入都重新扫描全部文件的问题。
- 修复搜索结果跳转后目标行只落在视口边缘、不容易确认的问题。

### 升级说明

- 已安装 0.8.12 或 0.8.13 的用户可在标题栏更新入口或“设置 → 更新”检查更新，应用会从 fork 的签名 feed 下载 0.8.14。
- 也可以直接下载安装包覆盖安装；设置、项目状态和日志仍在 `%APPDATA%\Lithe Desktop`。
- 安装包未签名，Windows 可能提示未知发布者。

### 兼容性与已知问题

- 本次仅提供 Windows x64 安装包。
- 更新 feed 位于 `https://github.com/zhustya/Lithe-IDEA/releases/download/desktop-update-feed/stable.json`，只覆盖个人 fork 的版本。
- 全文索引保存在内存中，每次启动应用后的第一次搜索仍需要读取工作区建立索引；20k 文件、约 1.5 GB 的工作区约需 2–4 分钟，期间可以继续输入，但冷查询可能超时并自动重试。
- 打开“包含 Git 忽略”“包含生成目录”或“跟随符号链接”等改变索引范围的选项后，该组合仍走文件清单扫描，需要重新建立对应变体的索引。

## English

Lithe Desktop 0.8.14 makes project and global search faster on large workspaces and makes the jump from a search result obvious.

### Downloads

- [Project homepage](https://github.com/zhustya/Lithe-IDEA)
- [Windows x64 installer](https://github.com/zhustya/Lithe-IDEA/releases/download/sourcegit-style-0.8.14/lithe-0.8.14-windows-amd64-setup.exe)
- [Windows x64 archive](https://github.com/zhustya/Lithe-IDEA/releases/download/sourcegit-style-0.8.14/lithe-0.8.14-windows-amd64.zip)
- [All downloads and SHA-256 checksums](https://github.com/zhustya/Lithe-IDEA/releases/tag/sourcegit-style-0.8.14)

### Highlights

The first search builds the full-text index in the background; once it is ready, rare keywords and non-ASCII words answer in milliseconds instead of tens of seconds, and complete counts no longer read every file.

#### ✨ New features

- Opening a project or global search result now scrolls the target line to the middle of the editor and flashes it, so the arrival is visible without hunting.
- The search panel shows "Building the search index…" while the index is built; a cold query that times out keeps searching, and the page is retried when the index is ready.

#### ⚡ Improvements

- The first project or global text query also asks Core to warm `workspace.searchIndex.warm` in the background, once per visibility variant; the index is released when the project closes.
- Non-ASCII queries now narrow candidate files with byte trigrams too, so Chinese words drop from seconds to milliseconds on the same workspace.
- Complete match counts reuse the same candidate set instead of reading the whole workspace for every query.
- Complete counts wait for a short pause in typing, so a burst of input no longer triggers repeated whole-workspace scans.

#### 🛠 Fixes

- Fixed rare keyword searches on large workspaces almost always timing out and rescanning every file after each keystroke.
- Fixed the target line of a search result landing at the edge of the viewport, where it was easy to miss.

### Upgrade instructions

- On 0.8.12 or 0.8.13, use the title bar update entry or Settings → Updates; the app downloads 0.8.14 from the signed fork feed.
- Or install the package over the existing app. Settings, project state, and logs stay in `%APPDATA%\Lithe Desktop`.
- The installer is unsigned, so Windows may warn about an unknown publisher.

### Compatibility and known issues

- This release ships a Windows x64 package only.
- The update feed at `https://github.com/zhustya/Lithe-IDEA/releases/download/desktop-update-feed/stable.json` covers only this fork's releases.
- The full-text index lives in memory, so the first search after each launch still reads the workspace to build it: about 2–4 minutes for 20k files and roughly 1.5 GB. Typing continues meanwhile, but a cold query may time out and retry automatically.
- Turning on options that change the index scope, such as Include Git-ignored, Include generated directories, or Follow symbolic links, still falls back to scanning the file list until that variant's index is built.
