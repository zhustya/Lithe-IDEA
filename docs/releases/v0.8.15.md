## 中文

Lithe Desktop 0.8.15 让项目搜索和全局搜索在大型工作区上更快，把“什么时候建立搜索索引”做成可调设置，并让点击搜索结果后的跳转一眼可见。

### 重点更新

打开项目后默认在后台建立全文索引，第一次搜索就是毫秒级；索引就绪后，罕见关键词和中文词的搜索从几十秒降到毫秒级，完整计数不再逐文件扫描。索引的建立时机可以在“设置 → 工具 → 搜索 → 搜索索引”里改。

#### ✨ 新功能

- “设置 → 工具 → 搜索 → 搜索索引”新增“打开项目时建立”开关：打开时项目一打开就在后台建索引，关闭时改为第一次搜索时建立。
- 点击项目搜索或全局搜索的结果打开文件时，目标行滚动到编辑器中间并淡出高亮，跳转位置不再需要自己寻找。
- 搜索面板在建立索引期间显示“正在建立搜索索引”，冷查询超时后保持“搜索中”，索引就绪会自动重查。

#### ⚡ 改进

- 项目搜索和全局文本搜索复用后台建立的全文索引，每个可见性变体只建一次；索引在关闭项目时释放。
- 索引构建等在 `ConfigureIndexing` 完成之后开始，避免按旧索引策略白建一份再丢弃。
- 中文等非 ASCII 查询也使用字节三元组收窄候选文件；同一工作区里中文词的搜索从十几秒降到毫秒级。
- 完整匹配计数复用同一候选集，不再为每个查询读取整个工作区。
- 完整计数在输入停顿后再开始，连续输入不会反复触发整库扫描。

#### 🛠 修复

- 修复大型工作区里罕见关键词搜索几乎必然超时、每次输入都重新扫描全部文件的问题。
- 修复搜索结果跳转后目标行只落在视口边缘、不容易确认的问题。

### 升级说明

- 已安装 0.8.12 或之后的个人 fork 版本，可在标题栏更新入口或“设置 → 更新”检查更新，应用会从 fork 的签名 feed 下载 0.8.15。
- 也可以直接下载安装包覆盖安装；设置、项目状态和日志仍在 `%APPDATA%\Lithe Desktop`。
- 安装包未签名，Windows 可能提示未知发布者。

### 兼容性与已知问题

- 本次仅提供 Windows x64 安装包。
- 更新 feed 位于 `https://github.com/zhustya/Lithe-IDEA/releases/download/desktop-update-feed/stable.json`，只覆盖个人 fork 的版本。
- 默认打开项目就建索引：20k 文件、约 1.5 GB 的工作区会在打开后读盘 2–4 分钟并常驻约 230 MB。小项目只多几 MB（47 个可搜索文件约 3–4 MB、0.1 秒）。不想在打开时占资源，就关掉“打开项目时建立”，改为第一次搜索时建立。
- 全文索引保存在内存中，每次启动应用后仍需要建立一次；打开“包含 Git 忽略”“包含生成目录”或“跟随符号链接”等改变索引范围的选项后，该组合仍走文件清单扫描，需要重新建立对应变体的索引。

## English

Lithe Desktop 0.8.15 makes project and global search faster on large workspaces, makes when the search index is built a setting, and makes the jump from a search result obvious.

### Downloads

- [Project homepage](https://github.com/zhustya/Lithe-IDEA)
- [Windows x64 installer](https://github.com/zhustya/Lithe-IDEA/releases/download/sourcegit-style-0.8.15/lithe-0.8.15-windows-amd64-setup.exe)
- [Windows x64 archive](https://github.com/zhustya/Lithe-IDEA/releases/download/sourcegit-style-0.8.15/lithe-0.8.15-windows-amd64.zip)
- [All downloads and SHA-256 checksums](https://github.com/zhustya/Lithe-IDEA/releases/tag/sourcegit-style-0.8.15)

### Highlights

A project now builds the full-text index in the background as soon as it opens, so even the first search answers in milliseconds; rare keywords and non-ASCII words drop from tens of seconds to milliseconds, and complete counts no longer read every file. When the index is built is a setting under Settings → Tools → Search → Search index.

#### ✨ New features

- Settings → Tools → Search → Search index gains "Build when a project opens": on builds the index in the background as the project opens, off defers it to the first search.
- Opening a project or global search result now scrolls the target line to the middle of the editor and flashes it, so the arrival is visible without hunting.
- The search panel shows "Building the search index…" while the index is built; a cold query that times out keeps searching, and the page is retried when the index is ready.

#### ⚡ Improvements

- Project and global text search reuse the index built in the background, once per visibility variant; the index is released when the project closes.
- The build waits until `ConfigureIndexing` finishes, so no index is built under a stale policy and thrown away.
- Non-ASCII queries now narrow candidate files with byte trigrams too, so Chinese words drop from seconds to milliseconds on the same workspace.
- Complete match counts reuse the same candidate set instead of reading the whole workspace for every query.
- Complete counts wait for a short pause in typing, so a burst of input no longer triggers repeated whole-workspace scans.

#### 🛠 Fixes

- Fixed rare keyword searches on large workspaces almost always timing out and rescanning every file after each keystroke.
- Fixed the target line of a search result landing at the edge of the viewport, where it was easy to miss.

### Upgrade instructions

- On 0.8.12 or a later fork build, use the title bar update entry or Settings → Updates; the app downloads 0.8.15 from the signed fork feed.
- Or install the package over the existing app. Settings, project state, and logs stay in `%APPDATA%\Lithe Desktop`.
- The installer is unsigned, so Windows may warn about an unknown publisher.

### Compatibility and known issues

- This release ships a Windows x64 package only.
- The update feed at `https://github.com/zhustya/Lithe-IDEA/releases/download/desktop-update-feed/stable.json` covers only this fork's releases.
- Indexing at project open is the default: a workspace of 20k files and about 1.5 GB reads for 2–4 minutes after opening and keeps about 230 MB resident. Small projects cost a few megabytes (47 searchable files about 3–4 MB in 0.1 s). Turn off "Build when a project opens" to build on the first search instead.
- The full-text index lives in memory, so it is built once after each launch. Options that change the index scope, such as Include Git-ignored, Include generated directories, or Follow symbolic links, still fall back to scanning the file list until that variant's index is built.
